# Smart Secretary — نظام السكرتير الذكي v1.0.0

نظام إدارة سكرتارية وأعمال احترافي لسطح المكتب (Windows) — عربي RTL بالكامل.

## الوحدات

لوحة قيادة ذكية • بحث موحد (Ctrl+K) • مهام (قائمة/كانبان/تقويم) • مواعيد (يوم/أسبوع/شهر/أجندة) •
عملاء CRM مع Timeline • اتصالات • ملاحظات • ملفات • إشعارات • مستخدمون وأدوار • سجل تدقيق •
مشاريع 101-108 ووحدات • حجوزات • مبيعات ومالية • 10 تقارير (PDF/Excel/طباعة) • مساعد ذكي عربي • نسخ احتياطي.

## أول تشغيل (حساب المدير)

لا توجد كلمات مرور افتراضية معروفة داخل الكود. عند أول تشغيل يُنشأ حساب `admin`
بكلمة مرور عشوائية قوية، وتُطبع مرة واحدة في طرفية الخادم وتُحفظ في:

```
data/.initial-admin-password      (صلاحيات 0600 — تُحذف تلقائيًا بعد تغييرها)
```

تغيير كلمة المرور **إلزامي** عند أول تسجيل دخول، وبعدها يُحذف الملف.

### تدوير الاعتمادات المعلنة (مهم لمن سحب المستودع)

قاعدة البذر `data/smart-secretary.db` المرفوعة في المستودع كانت تحتوي حسابات
بكلمات مرور معلنة (`admin/admin123` و`sara/sara1234`). أي تثبيت يسحب هذه القاعدة
كان سيرث تلك الاعتمادات. لذلك يفحص الخادم عند **كل إقلاع** تجزئات كلمات المرور
في جدول `users` مقابل قائمة كلمات معلنة/مسربة، وأي تطابق يُدوَّر فورًا:

* تُولَّد كلمة مرور عشوائية قوية لكل حساب مطابق.
* تُطبع مرة واحدة في طرفية الخادم وتُكتب في `data/.initial-admin-password` (0600).
* يُضبط `must_change_password=1` فتحجب بوابة `passwordChangeGate` كل المسارات
  (عدا قائمة بيضاء: `/health`, `/auth/login`, `/auth/me`, `/auth/change-password`,
  `/auth/logout`, `/settings/public`, `/brand/public`, `/public/*`) حتى التغيير.
* يُسجَّل الإجراء في جدول `data_repairs` للتدقيق.
* العملية idempotent: بعد التدوير لا تعود التجزئة مطابقة، فلا يتكرر الإجراء.

للتعطيل في بيئة اختبار فقط: `SS_SKIP_CREDENTIAL_ROTATION=1`.

| الخيار | الوظيفة |
|---|---|
| `SS_ADMIN_PASSWORD="..."` | ضبط كلمة مرور المدير الأولية (10 أحرف على الأقل) بدل العشوائية |
| `SS_JWT_SECRET` / `SS_AI_MASTER_KEY` | تجاوز مفاتيح التشفير عبر البيئة بدل الملفات |
| `POST /api/system/secrets/rotate` | تدوير المفاتيح (يُنهي كل الجلسات ويعيد تغليف مفاتيح AI) |
| `GET /api/system/secrets` | حالة المفاتيح + هل هي داخل المستودع (compromised) |

سياسة كلمات المرور: 10 أحرف على الأقل، فئتان من الأحرف، رفض الكلمات الشائعة
واسم المستخدم والتسلسلات والتكرار.

### حسابات الديمو
تُنشأ حسابات تجريبية معروفة فقط عند تفعيل "بيانات تجريبية" صراحةً من الإعدادات،
ووضع الديمو **مطفأ افتراضيًا** ولا يمكن تفعيله عندما `NODE_ENV=production`.

## الاختبارات

```bash
npm test                 # يشغّل الخادم على قاعدة بيانات مؤقتة ثم ينفّذ كل الأجنحة
npm run test:core        # جناح الأساس (دخول، صلاحيات، CRUD، مالية، حجوزات، تقارير، مساعد، نسخ) — 46
npm run test:regression  # جناح انحدار تدقيق 2026-09-19 (التحويلات، الشيكات، الذرّية، الملفات، AI…) — 139
npm run test:security    # جناح الأمان: تدوير الاعتمادات المعلنة + البوابة + سياسة كلمات المرور — 30
```

المجموع: **215 اختبارًا**. الأجنحة تعمل على نسخ مؤقتة من قاعدة البيانات ولا تلمس
`data/smart-secretary.db` الأصلي، وقابلة للتكرار تشغيلًا بعد تشغيل.

> `QA_KEEP=1` يُبقي قاعدة البيانات المؤقتة للتشخيص، و`QA_VERBOSE=1` يعرض سجل الخادم مباشرة،
> و`QA_ONLY=core|regression|security` يشغّل جناحًا واحدًا.

## الأمان

* لا اعتمادات دخول معروفة في الكود أو في قاعدة البذر — تدوير تلقائي عند الإقلاع (أعلاه).
* الأسرار (`JWT`، مفتاح تشفير مفاتيح AI) تُنشأ داخل `DATA_DIR` بصلاحيات 0600 ولا تدخل المستودع — راجع `.gitignore`.
* `GET /api/system/secrets` يعيد **حالة** المفاتيح فقط (بلا قيم) ويبين هل هي داخل المستودع/متتبَّعة في git.
* تحميل/معاينة الملفات عبر **تذكرة موقّعة قصيرة العمر** مرتبطة بالجلسة (لا JWT في الرابط) مع فحص صلاحية على الملف نفسه.
* قائمة بيضاء لامتدادات الرفع، وكل نوع غير موثوق (HTML/SVG/…) يُقدَّم كمرفق مع CSP صارم.
* CORS بالرفض الصامت: الأصل غير المدرج لا يحصل على `Access-Control-Allow-Origin` إطلاقًا (لا `*`) — `CORS_ORIGINS` للتخصيص.
* العمليات المالية متعددة الخطوات داخل معاملات ذرّية (`db.transaction`) — لا حالة نصف مكتملة، و`ROLLBACK` يلغي كل شيء.
* نقاط النظام (`/api/system/*`) تتطلب مستوى مدير، وسجل تدقيق لكل عملية حساسة.
* صلاحيات أدوات الذكاء الاصطناعي تمرّ بنفس مصفوفة صلاحيات المستخدم عبر `server/ai_permissions.js` — لا قدرة للـAI على ما لا يملكه المستخدم.

## بناء نسخة الإنتاج (على Windows)

المتطلبات: Node.js 20+ فقط — لا حاجة لأي أدوات بناء (قاعدة البيانات WASM خالصة بدون ترجمة).

```bash
npm install
npm run dist       # ينتج Smart-Secretary-Setup-1.0.0.exe في release/
```

> قاعدة البيانات بتقنية WASM خالصة (بدون أي وحدات أصلية)، لذا لا حاجة لأدوات بناء
> ولا لخطوات إضافية — `npm install` ثم `npm run dist` مباشرة على Windows.

المثبت: NSIS مع اختيار مجلد التثبيت + اختصارات سطح المكتب وقائمة ابدأ + إلغاء تثبيت.
البيانات تُحفظ في `%APPDATA%/Smart Secretary/data` وتبقى بعد التحديث/إعادة التثبيت.
