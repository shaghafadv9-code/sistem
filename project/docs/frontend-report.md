## 1. المنهجية

- **لم يُبنَ نظام جديد** ولم تُحذف أي صفحة/شاشة عاملة.
- تمت **مراجعة كامل الواجهة** أولًا: `App.jsx` (خريطة المسارات)، `components/Layout.jsx` (القائمة الجانبية)، `components/ui.jsx` (المكوّنات الأساسية)، `lib/api.js`، `lib/store.js`، `lib/format.js`، ثم كل صفحة في `pages/`.
- التوسعة تمت **بنفس الهوية والتصميم**: نفس كلاسات CSS ونفس ألوان النظام (CSS Variables) ونفس مكتبة الأيقونات الداخلية — بلا أي مكتبة جديدة.
- RTL كامل (`dir="rtl"` + `lang="ar"`) وخط **IBM Plex Sans Arabic** (محلي داخل `assets/fonts` بدون إنترنت).

## 3. الصفحات المطوّرة (بدون كسر أي شيء)

- **`pages/Reports.jsx` — تطوير جوهري (بند 26/27/22):**
  - شريط **فلاتر لكل تقرير** يُبنى ديناميكيًا من `def.filters` القادمة من الخادم: `from/to/project/unit/client/broker/employee/account/method/status/expenseCategory/building/floor/propertyType/floorType/stage/bool`.
  - عرض `meta` الرسمي: **رقم التقرير + التاريخ + المستخدم + الفلاتر المطبقة** (بند 27).
  - عرض المبالغ منسّقًا (`fmtN`) بدل النص الخام، وترويسة الطباعة الاحترافية كما هي (هوية الشركة + الشعار).
  - أيقونات جديدة لبطاقات التقارير الجديدة (تحصيلات/متأخرات/مصروفات/عمولات/مبيعات المشاريع/اهتمامات/غير متابعين/أكثر الطلبات...).
- **`pages/Sales.jsx` / `pages/Reservations.jsx` / `pages/Projects.jsx` / `pages/Units` (داخل Projects):** بقيت كما هي وتعمل مع الحقول والأحداث الجديدة في الخادم (جدول الدفعات، الحالات، سجل حالة الوحدة) — راجع `docs/FINAL-REPORT.md` للتفاصيل الخادمية.
- **`components/Layout.jsx`:** أقسام القائمة الجانبية أعيد تنظيمها وأضيفت الصفحات الجديدة بصلاحيات دقيقة:
  - العملاء: العملاء / اهتمامات العملاء / مسار البيع / سجل التواصل والمتابعات / الاتصالات
  - العقارات والمعاملات: المشاريع / الوحدات / الحجوزات / **عروض الأسعار** / **العقود** / المبيعات / **جدول الأقساط**

- **`App.jsx`:** تسجيل 13 مسارًا جديدًا (lazy + ErrorBoundary لكل صفحة) مع ربط كل مسار بصلاحية الوحدة (`clients, interests, pipeline, communications, quotations, contracts, schedule, accounts, finance, expenses, commissions, statements, approvals`).

## 5. قواعد الواجهة المطبقة (بند 32)

- تصميم النظام كما هو (لم يُغيَّر الثيم العام ولا التخطيط).
- عربي RTL كامل وقائمة جانبية مرتبة بالأقسام؛ **الشريط العمودي يعمل** لأن حاويات الصفحات تحتفظ بـ `overflow-y:auto` (لم يُضف أي `overflow:hidden` جديد).
- كل صفحة جديدة فيها: **حالة تحميل** (Skeleton)، **حالة فراغ** (Empty برسالة عربية)، **تأكيد** قبل أي عملية حساسة (Confirm/Modal)، و**رسائل Toast** للنجاح/الفشل.
- **الطباعة** كلها داخل `print-area` + `no-print` فالمطبوع = التقرير فقط (بند 27).

## 6. الحماية والصلاحيات في الواجهة (بند 28)

- إخفاء عناصر القائمة والمسارات حسب `can(module[, action])` — لا يظهر للمستخدم ما لا يملك صلاحيته، والخادم يتحقق مجددًا (لا اعتماد على الواجهة وحدها).
- تنزيلات Excel تمر بـ `Authorization: Bearer` (لا تُفتح روابط عامة).
- لا تُخزَّن كلمات مرور أو أسرار في الواجهة؛ الجلسة عبر التوكن المخزَّن من نظام الدخول الحالي.

## 7. التحقق

- بناء الواجهة: `cd client && npx vite build` → **ناجح** (كل الصفحات الـ13 تُنتَج كـ chunks منفصلة).
- تشغيل: `npx vite --host 0.0.0.0 --port 5173` (بروكسي `/api` و`/uploads` إلى `127.0.0.1:3847`) → الصفحة والـ API يردّان 200.
- صفحات كانت بلا تحقق سابق (Contracts, Interests, Pipeline, Communications) أصبحت مُتحقَّقة بالبناء.

## 8. المشاكل المتبقية (واجهة)

1. رسائل واتساب **تُفتح يدويًا** بضغطة المستخدم (شرط البند 20) — لا إرسال جماعي آلي؛ خيار WhatsApp Business API موجود في الخادم للإرسال الآلي عند التفعيل.
2. كشوف الحسابات في صفحة الكشوف لا تحتوي ترقيم صفحات للنتائج الطويلة (تُصدَّر Excel للكامل).
3. سجل حالة الوحدة (بند 23) يُعرض في ملف الوحدة داخل صفحة المشاريع؛ لا صفحة مستقلة له (لا حاجة وظيفية، النطاق محفوظ).
