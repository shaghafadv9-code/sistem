تم تنفيذ التحديث المطلوب على **النظام القائم بالكامل دون إعادة بناء من الصفر**: لم تُحذف أي شاشة أو وظيفة عاملة، وتمت مراجعة الواجهة والخادم وقاعدة البيانات والواجهات البرمجية والصلاحيات والتقارير أولًا، ثم أُضيفت الوحدات الجديدة داخل نفس التصميم والهوية.

النتيجة العملية: النظام أصبح **مصدرًا موحدًا لكل ريال (One Source of Truth)** — كل مبلغ له حساب مالي ومرجع ومرفق وتاريخ ومستخدم وسجل تدقيق، ولا يوجد أي حذف فعلي للبيانات المالية (يُستبدل بحالات إلغاء/استرداد معاكس)، ولا يُسمح بدفعة تتجاوز قيمة العقد، ويُمنع أي تعارض بين المدفوع والمتبقي وصافي القيمة العقدية.

**أرقام فعلية بعد التنفيذ:** 30 جدولًا • 12 حسابًا ماليًا • 66 حركة مالية متولّدة تلقائيًا • 24 تقريرًا (منها 14 جديدًا) • 538 نقطة وصول API • 29 شاشة عربية RTL.

**أبرز ما تحقق:**
- نظام مالي كامل: حسابات (نقدي/بنك/مشروع/أخرى) + حركات + أرصدة تُحسب تلقائيًا لا تُكتب يدويًا.
- إعادة بناء الدفعات بكل الحقول (عميل/بيع/عقد/وحدة/مشروع/مبلغ/تاريخ/طريقة/حساب/بنك/مرجع/شيك/حالة/مرفق/ملاحظات/مستخدم).
- العربون دفعة حقيقية مرتبطة بالحجز والحساب ثم تتحوّل إلى بيع دون احتساب مزدوج (وتم ترحيل البيانات القديمة).
- جدول أقساط لكل عقد/بيع + تقرير متأخرات (أيام التأخير، آخر دفعة، آخر متابعة).
- كشوف حساب العميل والمشروع مع Drill-down، قابلة للطباعة وPDF وExcel.
- سجل حالات الوحدة غير القابل للحذف (unit_status_history).
- CRM كامل: اهتمامات متعددة، فلاتر متقدمة، مطابقة الاهتمامات بالوحدات، سجل تواصل ومتابعات، مسار بيع بعشر مراحل بالتواريخ.

## 5) قاعدة البيانات

- **30 جدولًا** (منها 14 جديدًا) + جدول الهجرات.
- **الهجرات:** M1 بناء المالية وCRM · M2 الحسابات والتصنيفات الافتراضية والمراحل والصلاحيات · M3 ترحيل العربونات والعقود وجداول الأقساط والمراحل.
- **سلامة البيانات:** مفاتيح أجنبية منطقية (عميل/وحدة/مشروع/بيع/مستخدم/حساب) + قيود إلزامية للمبالغ.
- **الفهارس:** أكثر من 60 فهرسًا على أعمدة الفلترة والتواريخ والحالات.
- **عدم الحذف:** لا حذف فعلي للبيانات المالية — إلغاء/استرداد مع قيد معاكس.
- **الأداء:** ترقيم صفحات (limit/page) على كل القوائم الكبيرة.

## 6) الأمان والصلاحيات

- كلمات المرور مُشفَّرة ولا تُعاد في أي رد API، وجلسات JWT بصلاحية زمنية.
- صلاحيات على مستوى الوحدة والحركة (عرض/إضافة/تعديل/حذف/اعتماد/تصدير).
- استعلامات مُعاملية، واختبار محاولات حقن SQL رُفضت، ومنع XSS، وترويسات أمان، وحماية مسارات المرفقات.
- ربط الملفات بالكيان: عميل/وحدة/مشروع/حجز/بيع/عقد/دفعة/مصروف/عرض/استرداد/اهتمام/حساب.
- سجل تدقيق `audit_logs` لكل عملية مالية أو اعتماد أو تغيير حالة.

**مصفوفة صلاحيات مختبرة:** مدير النظام (كامل) · المحاسب (كامل ماليًا، بلا اعتماد مصروفات) · السكرتيرة (لا ترى الحسابات المالية، تتابع الاهتمامات).

## 10) المشاكل المتبقية والقيود

1. **إرسال واتساب:** الرسائل تُجهَّز وتُنسخ وتُفتح من المستخدم (لا إرسال جماعي آلي) التزامًا بالمتطلب — التشغيل الآلي جاهز عبر القوالب ويمكن ربط واتساب Business API عند تفعيل الحساب.
2. **التقارير الطويلة:** تُصدَّر Excel كاملة، وشاشة العرض تعرض أول 200 سجل — يمكن إضافة ترقيم صفحات للطباعة عند الحاجة.
3. **اعتماد المدير:** المصروف فوق السقف (5000 افتراضيًا) وأي خصم/تعديل حساس يتطلب اعتماد المدير — سلوك مقصود والسقف قابل للتعديل.
4. **بيانات تجريبية:** قاعدة البيانات تحتوي بيانات العرض والاختبار — تُفرَّغ عند التشغيل الفعلي مع الاحتفاظ بنسخة احتياطية.
5. **بيئة التشغيل:** كلمات المرور الافتراضية للمستخدمين التجريبيين ما زالت مفعّلة — يجب تغييرها قبل النشر الإنتاجي.
