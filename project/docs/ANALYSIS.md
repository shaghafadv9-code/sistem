# تحليل المشروع — Smart Secretary

تاريخ التحليل: 2026-09-17

## 1. الوضع الحالي

تم فحص مساحة العمل بالكامل: **فارغة تمامًا — لا يوجد نظام حالي**.

| البند | النتيجة |
|---|---|
| Architecture حالية | لا توجد — بناء جديد من الصفر (Greenfield) |
| قاعدة بيانات | لا توجد — تصميم جديد بالكامل |
| صفحات/مكونات | لا توجد |
| صلاحيات | لا توجد — تصميم مصفوفة كاملة |
| API/خدمات | لا توجد |
| أخطاء قائمة | لا يوجد (لا شيء للترقيع) |
| قابل لإعادة الاستخدام | لا ينطبق |

**القرار الهندسي:** بما أنه لا يوجد إرث تقني، تم اعتماد **Clean Architecture من الصفر** بدل أي ترقيع، مع تصميم كل الوحدات المطلوبة (العقارات، الحجوزات، المالية) كجزء أصيل من النظام وليس إضافات لاحقة.

## 3. مخاطر تمت معالجتها تصميميًا

1. **PDF عربي:** مكتبات PDF البرمجية لا تشكّل الحروف العربية — الحل: محرك طباعة HTML (يستخدم محرك Chromium داخل Electron) فينتج PDF عربيًا مثاليًا.
2. **صلاحيات شكلية:** ممنوعة — كل مسار API يمر عبر `requirePerm(module, action)` والواجهة تعكس نفس المصفوفة.
3. **فساد البيانات المالية:** كل الحسابات في الخادم مع تحقق صارم (خصم ≤ سعر، دفعة ≤ متبقي...) + قيود CHECK في قاعدة البيانات.
4. **الحجز المزدوج:** فحص حالة الوحدة ذريًا قبل الحجز + تحديث فوري للحالة.
5. **فقدان البيانات:** نسخ احتياطي بضغطة + استعادة آمنة (تتطلب إعادة تشغيل).
6. **النمو المستقبلي:** معمارية وحدات (modules) ومصادر عامة (generic resources) تسمح بإضافة كيانات جديدة بسطور قليلة.
